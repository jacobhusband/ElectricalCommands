# ACIES Desktop UI/UX review

Reviewed September 4, 2026 by launching the local Python/pywebview application and clicking through its live interface at its default window size, approximately 1400 × 900. This is an interaction review of the current local checkout and data, not a comprehensive accessibility or engineering-calculation audit.

## Main recommendation

Make daily work visible first, give each project an obvious entry point, and reduce the number of controls competing with project information. The existing functionality already supports much of this simplification.

## Findings, in recommended order

### 1. Make project cards easier to read and operate

**Observed:** Each delivery card has a separate row of roughly eight icon actions. These sit above the project name and deliverable, giving controls the first visual position. Most icons are very dim until hover, but their outlined containers still add clutter. Delete is next to edit.

**Code evidence:** `styles.css:10019` defines the action row; `styles.css:10075` sets action buttons to 22 × 22 pixels. Parent and child opacity rules further reduce inactive action visibility.

**Recommendation:** Lead with project name, deliverable, due date and status. Keep a labeled Open action, a status control, and a More menu. Put deletion and infrequent actions in More; retain quick access to frequently used engineering tools. Aim for comfortably sized desktop targets, such as 32–36 pixels, without nested opacity reductions.

**Verify:** A user can identify the next deliverable and open it without hovering over several icons. Keyboard focus reveals all remaining actions clearly.

### 2. Provide a focused daily-work view

**Observed:** The initial current-week board had 2 items in “None” and 14 in “Complete.” Completed cards occupied most of the populated area. Switching to list view exposed All timeframe and All status, with October work appearing first. Selecting This week and Incomplete reduced the screen to the two actionable items.

**Recommendation:** Add a visible “Needs attention” preset combining unfinished current-week work and older overdue items. Collapse completed work with a count. Preserve an easy All work view and the user's chosen view. Use “No status” instead of “None”; do not silently assume every unset status means work has not started.

**Implementation starting point:** Board column configuration in `script.js:10400`; board rendering in `script.js:26685`.

**Verify:** Overdue unfinished work remains visible across week boundaries. Switching between list and board communicates any change in scope.

### 3. Make opening a project predictable

**Observed:** Clicking the project name did not open its in-app details. The pencil opened Edit Project, while the small document icon opened the full project page. Project tools had a separate wrench menu.

**Code evidence:** `script.js:26128` binds project-name activation to opening the filesystem path. `script.js:26657` builds the card's project identity.

**Recommendation:** Make the name open the project workspace and provide an explicit folder button for the directory. Alternatively, preserve name-to-folder behavior for established users and add a prominent labeled “Open project” action. Bring notes, deliverables and project tools together behind a consistent project header.

**Verify:** Opening a project, editing its metadata, and opening its folder are clearly distinguishable before clicking.

### 4. Fix timesheet headings during scrolling

**Observed:** Scrolling to lower timesheet entries kept the week/total toolbar visible but lost the Mon–Sun column headings. Long project names and service descriptions were also clipped. Add-entry actions were below the existing rows.

**Code evidence:** `styles.css:10681` creates an overflow container; `styles.css:10703` already attempts sticky table headings with `top: 0`. The live result shows that the current scrolling/toolbar arrangement does not keep them visible.

**Recommendation:** Correct the scroll-container and sticky-offset relationship, keeping day headings below the toolbar. Put Add entry in the toolbar, with Project and Manual choices. Provide an expanded row or editable detail view for long descriptions. Consider hiding unused weekend columns behind an explicit toggle.

**Verify:** Scroll through the full existing week and confirm the day labels remain visible and aligned with inputs. Repeat near the supported minimum window width.

### 5. Make project selection searchable in Panel Schedules

**Observed:** Opening Panel Schedules from Tools preselected a project unrelated to the project just inspected. Its project selector opened a long native dropdown with no visible search field and many similar client names.

**Code evidence:** `index.html:2647` uses a native select. `script.js:30785` renders options and falls back to the first project when the current selection is invalid.

**Recommendation:** Offer search by project number, client and address, with recent projects first. Preserve project context when launched from a project. From global Tools, use an explicit “Choose project” state unless there is a clear remembered selection.

**Verify:** A project can be located by number or address, and linking a workbook always makes the target project obvious.

### 6. Recover from unhelpful canvas views

**Observed:** The Atherton Panels canvas opened at 182% zoom with oversized regions and almost no useful photo content visible. Clicking Fit immediately showed the photo layout at 22%.

**Recommendation:** Preserve useful saved views, but offer a prominent “Show all content” recovery action when the viewport has little meaningful content in view. Provide explicit zoom-in, zoom-out and percentage controls. On first open, fit content after its dimensions are known.

**Implementation starting point:** `script.js:43525`, `fitCanvasView`.

**Limit:** This observation does not establish whether the original view resulted from a saved pan/zoom state, image loading, or initialization. Investigate before changing restoration behavior.

### 7. Separate everyday tools from maintenance

**Observed:** The Tools tab mixed daily engineering tools with a large grid of AutoCAD plugin Update/Uninstall controls. Cards such as XREF and Archive did not show their effect without additional exploration. The project wrench menu put 11 tools in a flat list.

**Code evidence:** Tool descriptions exist in `index.html`, but `styles.css:3441` hides `.tool-card-body` on the Tools tab.

**Recommendation:** Restore short descriptions for ambiguous tools. Group the project menu by drawing operations, calculations and documents. Move plugin maintenance into Settings → AutoCAD → Plugins, with a compact update indicator in Tools when needed.

**Verify:** Users can distinguish XREF cleanup from path repair and understand Archive before running either action.

### 8. Reduce conflicting date and status signals

**Observed:** Completed deliverables retained prominent red date pills. Several cards displayed two dates with little visible distinction beyond a lock icon. The edit form explains Internal due date and Hard deadline more clearly than the cards do.

**Recommendation:** Use labeled dates such as “Target Sep 4” and “Deadline Sep 9.” De-emphasize historical dates on finished items. Reserve urgent date treatment for unfinished work requiring attention. Keep text labels alongside color.

**Verify:** Users can distinguish a completed item with a past deadline from work that is currently overdue without opening the editor.

### 9. Organize Settings by purpose

**Observed:** Settings is a long scrolling modal combining identity, integrations, sync configuration, timesheets, filesystem diagnostics, AutoCAD selection, cleanup defaults and tool defaults. “Force save” and “Write test file” sit in the ordinary timesheet settings area. Sync setup exposes environment-variable instructions.

**Recommendation:** Use sections or navigation for General, Timesheets, AutoCAD, and Integrations. Move file paths, test writes and repair actions into Diagnostics. Give configuration problems a concise explanation and a setup/help destination.

**Implementation starting point:** `index.html:1565`; timesheet diagnostics at `index.html:1647`.

### 10. Simplify project creation and visual hierarchy

**Observed:** New Project starts with a reasonably small four-field form and supports Escape. Project Path is text-only, without a visible Browse action. Main screens often combine a header, large outer panel, inset toolbar, nested card borders and small muted text. The Wire Sizer uses a distinctly brighter theme than its surrounding dialog.

**Recommendation:** Keep the staged creation flow; add a folder picker beside Project Path. Reduce redundant panel borders and vertical spacing above work content. Increase the readability of secondary labels. Make embedded tools respect the app theme while retaining the Wire Sizer's clear input/result hierarchy.

## What already works

- The four main navigation tabs are easy to understand.
- Existing timeframe/status filters can isolate useful work without new backend functionality.
- New Project is concise, initially focuses the ID field, and Escape dismissed it correctly.
- Project pages provide readable notes, breadcrumbs and subpages.
- Panel Schedules has an informative empty state and a direct Choose Excel file action.
- Wire Sizer gives its main result strong visual priority and labels its inputs clearly.
- Timesheets shows a prominent weekly total and useful daily totals.

## Suggested implementation sequence

1. Fix timesheet sticky headings; improve card target size/contrast; rename None; reduce alarm styling on completed dates.
2. Simplify card actions, add a clear project-open action, and introduce a Needs attention preset.
3. Add searchable project selection, canvas view recovery and better Tools/Settings organization.

Validate these changes in the live application with the existing populated data. No backend data-contract changes are inherently required for these recommendations.

## Review scope and resulting state

Explored Projects board and list, timeframe/status filters, existing-project editor, New Project, project notes/subpages/canvas, Pages overview, project tool menu, Tools overview, Wire Sizer, Panel Schedules entry/chooser, Timesheets and Settings. Did not run CAD operations, export files, submit timesheets, edit project fields, or alter integration settings. Engineering calculation accuracy, external file workflows, light mode, and minimum-size layout remain untested.

The application was left running on its original current-week board. List filters were restored to All timeframe and All status. Canvas Fit saved its view at 22%; photo content was not edited. No application source code was changed for this review. This report is the only added repository file.
